## Fresh-process control

After adding the production BOS platform resource as the `platform` MCP server,
the first fresh Codex process failed during startup because its stored OAuth
refresh token had already been consumed. The server returned
`invalid_grant: Refresh token replay detected`. That startup failure prevented
tool discovery and reproduced the text-only “no active BOS MCP connection”
response.

The stale credential for only `platform` was removed with `codex mcp logout
platform`. No OAuth authorization was completed. A second fresh, ephemeral
Codex process then received the exact customer prompt. Its trace is thread
`01a0638a-48a9-7641-97f0-67b850491231` and establishes this sequence:

1. Codex loaded the installed BOS 0.4.72 Plugin Console skill.
2. Codex selected `platform.bos_get_context` for the requested BOS data.
3. The tool descriptor was available before consent.
4. The signed-out call returned `isError: true`, the text `Authentication
   required.`, and `_meta["mcp/www_authenticate"]` with the canonical protected
   resource URL, `error="invalid_token"`, and
   `error_description="Authentication required"`.
5. No business data or authenticated operation was exposed.

This proves the deployed server and a fresh Codex process satisfy the requested
pre-authentication selection and challenge contract.
