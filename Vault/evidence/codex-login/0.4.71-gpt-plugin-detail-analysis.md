## Verified renderer path

`webview/assets/plugin-detail-page-DWV0NZoE.js` imports the app merge exported
as `CW` and invokes it at byte offset 180169 with connector metadata, directory
apps, and the plugin's declared apps.

The exported implementation is `kXa` at byte offset 7238988 of
`webview/assets/app-initial-B6Gk5KCN.js`. For every declared plugin app it:

1. looks up connector metadata by app ID;
2. returns `null` when metadata is absent or the metadata name equals the raw
   ID; and
3. removes every `null` result before the plugin-detail surface receives its
   `apps` collection.

The declared BOS app and its native action are therefore removed before row or
button rendering.

The same build contains `Zbl` at byte offset 12987130 of the same initial
bundle. That install/connect lifecycle merge preserves a required app and
resolves optional values through fallbacks:

- connector metadata;
- directory app data; then
- plugin-declaration data.

This existing fallback proves that missing connector metadata does not require
discarding the app.

## Account-state regression event

The archived 2026-08-29 Codex task provides the missing causal event. Its
read-only uninstall plan found the installed account wrapper
`dev-6a932992592081919cdc88c60e4ff2dd@created-by-me-remote` and planned to
uninstall it before deleting the created app. The authorized execution then
failed specifically at the second `plugin/share/delete` operation with HTTP
404. The implementation performed `plugin/uninstall` first, so the account
wrapper was removed before the task stopped.

The current app-server `app/read` response returns no metadata and marks the
prefixed and canonical 6a7cb and 6a932 identities missing. Paginated live
`app/list` results through the alphabetical BOS range contain no BOS or
Business Operating System app. Every request and response was written to the
bounded redacted diagnostic log. This proves the package can remain installed
while its account registration has been removed. It also explains why package
rollback and cache resets cannot restore the native row.

## Correlated live diagnostic

On 2026-09-01 at 19:29 America/Denver, the repository-owned read-only
diagnostic ran against the authenticated Codex account with tracing enabled.
Every request was paired with a response through a redacted `request_id`.

- `plugin/read` returned `bos@bos-education-center` version `0.4.71` as
  installed and enabled.
- Its `apps` collection contained the required
  `plugin_asdk_app_6a7cb1cc330c81918aa63d96aeeaba91` declaration.
- The declaration arrived with its raw ID as `name`, no description, no
  category, one generated install URL, no app templates, and no MCP server.
- The forced created-by-me account-plugin listing returned no marketplaces or
  plugins.
- The authenticated connector metadata GET for that exact prefixed ID returned
  HTTP 404 with `{"detail":"Connector not found"}`.
- The GPT host identified itself to the diagnostic as Codex Desktop
  `0.151.0-alpha.7.2`.
- The same authenticated read-only probe returned HTTP 404 for both known
  replacement IDs,
  `plugin_asdk_app_6a932992592081919cdc88c60e4ff2dd` and
  `plugin_asdk_app_6a95a014a0a08191a9e6d16453a8b831`. The current account has
  no resolvable historical or replacement BOS connector that Git can select.
- The unprefixed historical `asdk_app_6a7cb...` form also returned HTTP 404,
  confirming that prefix substitution cannot repair the registration.

This proves that package receipt and display are separate. The package loader
receives the required app. The connector registry cannot resolve it. The
plugin-detail merge then removes the app and its action because the optional
metadata request failed. Connection inventory, OAuth grant, MCP initialization,
and tool discovery are downstream and were not needed to reproduce Issue
#0001.

The adjacent Issue #0002 customer-prompt trace likewise had no BOS catalog
entry, BOS tool selection, or BOS transport call. The connector resolution
failure is therefore the leading shared upstream cause; the server's separately
observed unauthenticated MCP response is not causal evidence for that chat
failure.

The reproducible command is:

```bash
npm run diagnose:codex-app -- --format json
```

It writes redacted NDJSON request/response events to standard error and the
structured verdict to standard output. `BOS_HTTP_DEBUG=0` disables tracing when
quiet output is explicitly required.
