# Oracle review: release 0.4.71 Codex Login regression

Date: 2026-09-01

## Scope

Review the complete release diff from `origin/main` through
`codex/release-v0.4.71`, including the exact registered-app restoration,
canonical package model, generated clients, bounded local package convergence,
runtime verification, regression tests, release metadata, corrected incident
history, and all new Vault manifests. BOS server code and infrastructure remain
outside the repository and outside this diff.

## Findings

### P0: GPT client suppresses the required persistent action

The 0.4.71 package loads the exact required root BOS app declaration, while GPT
build 26.825.51511 resolves no connector metadata for that declaration. The
client's plugin-detail merge discards a declared app when metadata is absent or
its resolved name is only the raw ID. The app row and its action therefore
never reach rendering. This violates `contracts/codex-login-surface.v1.json`:
connector metadata, connection inventory, grant state, and callable tools may
select **Connect** or **Reconnect** and may shape the subsequent flow; none may
control visibility. The same rule applies when the request for any of those
inputs fails. Correct the GPT client renderer and rerun the visual AC.
Build-scoped inspection identifies the exact inconsistent paths: plugin detail
uses `kXa`, which returns `null` and filters the app, while the install/connect
lifecycle uses `Zbl`, which preserves the app and falls back through connector,
directory, and plugin-declaration data. Apply the established fallback to the
plugin-detail merge.

### P0: required GPT UI Login/Connect screenshot is absent

The release changes the Codex Login display binding, while
`Vault/evidence/codex-login/0.4.71-connect-button.png` is absent. Package and
transport evidence cannot prove the native control rendered. Capture the
version-matched GPT client plugin page with the BOS Login or Connect control
visible, add that PNG to the required path, inspect the image, rerun the release
gate, and submit the complete updated diff for a fresh Oracle review.

### P0: separately owned request-time sign-in acceptance remains blocked

Issue #0002 remains owned by its separate implementation task. The deployed BOS
resource's synthetic HTTP 401 observation has been reclassified as valid
protected-resource behavior and is not causal for the customer turn. The exact
turn never loaded BOS or contacted that endpoint because the registered-app
connector failed resolution and BOS was absent from the conversation catalog.
Restore that connector ownership so the host can render native login before
loading authority-scoped tools. Its
version-matched visual artifact,
`Vault/evidence/codex-login/0.4.71-request-time-sign-in-button.png`, is absent.
Complete Issue #0002 under its owning client/account and task boundaries, capture that
independent screenshot, and preserve the separation between request-time auth
activation and Issue #0001's persistent plugin-page action.
