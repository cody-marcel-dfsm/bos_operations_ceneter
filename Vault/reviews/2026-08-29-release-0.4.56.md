# Release 0.4.56 review

## Scope

Review of the filesystem-only BOS cache reset, its generated client guidance,
and the 0.4.56 patch release.

## Findings

- `scripts/reset-bos-client-caches.mjs:30-43` rejects a relative home,
  filesystem-root home, and every target outside its explicit cache root.
- `scripts/reset-bos-client-caches.mjs:45-89` validates package ownership,
  rejects unexpected cache entries and symlinked cache roots, and verifies the
  retired remote-wrapper identity before a target becomes removable.
- `scripts/reset-bos-client-caches.mjs:91-145` selects only individual BOS
  catalog files and the validated BOS package/wrapper caches below
  `~/.codex/plugins/cache`, `~/.codex/cache`, and
  `~/.claude/plugins/cache`.
- `scripts/reset-bos-client-caches.mjs:149-176` requires exact confirmation,
  completes the full plan before deletion, and verifies every selected path is
  absent afterward.
- `scripts/uninstall-bos-all-clients.sh:6` converts the legacy destructive
  entrypoint into an alias for the bounded reset. The previous implementation
  that mutated accounts, registrations, source-adjacent state, and other
  clients is deleted.
- `tests/client-cache-reset.test.mjs:42-78` proves that source marketplace
  manifests, personal skills, global state, Claude marketplace state, Gemini,
  Copilot, the shared BOS document cache, and an unrelated catalog file all
  survive an applied reset.
- `tests/client-cache-reset.test.mjs:80-123` proves dry-run behavior, exact
  confirmation, all-target preflight, rejection of unrelated cache content,
  and refusal to use `/` as the home.
- `Vault/docs/architecture.md:210-219` fixes the durable deletion-authority
  boundary, and the canonical runbook at
  `source/platform/bos-guided-support/references/client-runbooks.md:21-41`
  communicates the same boundary to every generated client.

No correctness, security, credential, private-data, or release-blocking finding
remains.
