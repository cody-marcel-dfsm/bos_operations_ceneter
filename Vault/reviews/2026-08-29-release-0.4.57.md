# Release 0.4.57 architecture review

## Scope

Reviewed the complete versioned release diff from `0.4.56` to `0.4.57`,
including the in-memory Plugin Console routing fix, deterministic package
transformation, generated Claude/Codex/Copilot/Gemini clients, release metadata,
tests, Vault sources, and index history.

## Findings

No material findings.

## Evidence

- `source/platform/bos-plugin-console/SKILL.md:8-17` routes broad plugin and
  server-settings requests to the conversation-native, memory-only console and
  excludes customer initialization and settings-cache access.
- `source/platform/bos-plugin-settings/SKILL.md:17-28` performs that routing
  before product preflight or filesystem access and reserves typed settings
  initialization for one named plugin property.
- `scripts/lib/package-model.mjs:16-20,366-369` keeps BOS connection recovery,
  console routing, and broad runtime settings routing independent of subservice
  customer initialization during deterministic generation.
- `tests/plugin-console.test.mjs:44-73` covers the reported request phrase and
  verifies the generated Education Center packages contain no customer-settings
  preflight on the broad settings path.
- `tests/package-model.test.mjs:194-243` covers canonical transformation and
  Claude, Codex, Copilot, and Gemini generation behavior.
- `Vault/specs/plugin-service-console.md:10-20` and
  `Vault/docs/architecture.md:70-80,255-277` preserve one root BOS connection,
  server-derived authority, memory-only presentation, and domain-specific
  initialization ownership.
- Canonical package, BOS, and Education Center manifests and every generated
  active-client manifest consistently identify release `0.4.57`.
- `npm run release:check` regenerated two active products for all four clients,
  passed the package/skill/credential scan, passed the single-BOS MCP contract
  with zero violations, and passed all 186 tests.
- `git diff --check` passed.

The release introduces no client-owned authority, provider credential handling,
local service, runtime server mutation, or independent subservice connection.
Canonical enablement and provider actions remain server-authorized through the
root BOS connection and the documented Router-to-PO-to-GO boundary.
