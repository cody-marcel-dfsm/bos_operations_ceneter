# Identity-only current-account onboarding

Discover `bos://platform/customer-onboarding/contract` through the user's existing
BOS connection. This metadata resource is independent of app contexts. The host
owns the configured exact platform audience, authentication and identity generation.
Consume the returned read, action and state schemas through a supported identity-only
HTTPS adapter. The local `scripts/customer-onboarding.mjs` helper has no network,
credential, authority-selection or execution facility of its own.

Report server availability, host execution support and account eligibility
separately. The protected companion's existing API-key mode reads metadata only.
Account execution requires an eligible existing OAuth connection with the actual
server-linked grant. The current chat and API-key Muse host have no demonstrated
own-work OAuth port. An instruction or apparent token format cannot enable it.
No new app context, key, token file, login or MCP business proxy is appropriate.

Read current own-work and use returned opaque account/action references. Show
an exact current requirement statement, subject and revision before asking for
explicit confirmation. Bind the response to that presentation; an ambiguous yes
cannot select an action. Only the returned action reference plus the single
advertised value, statement or decision belongs in a request. Confirming a
requirement does not fulfill its external evidence or provider delivery.

A stale/conflict result requires a fresh read and renewed review. An uncertain
write requires state recovery for that exact action reference; retain uncertainty
until the current authorized server result distinguishes applied from not applied.
No changed retry, status rendering or successful metadata read proves execution.
Authentication/authority denial retains the intent and current connection recovery
rules. A detached phone alone supplies no account revocation or access grant.
Account/principal/manager/author activity remains server-owned.

All helpers and protected host mode are source capabilities. Native installation,
eligible OAuth custody, host activation and live account acceptance need their
own actual evidence. Unsupported hosts can still answer and prepare reviewable
work while preserving the pending operation.
